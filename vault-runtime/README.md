# Vault runtime: full Obsidian in a container

The WATTSON vault runtime (ADR 0001): the Obsidian Linux desktop app runs
under Xvfb in a container, the `obsidian` CLI talks to the live instance,
and the GUI is viewable in a browser via noVNC. Validated in Phase 0
(2026-09-22); this directory was the Phase 0 spike (`spike/obsidian/`) and
was renamed on 2026-09-27 now that the runtime is a stable component.

## Layout

Stable component:

- `Dockerfile` — ubuntu 24.04 + Electron deps + Obsidian 1.13.7 .deb + Xvfb + TigerVNC + noVNC + nginx
- `entrypoint.sh` — Xvfb :99, x11vnc :5900, noVNC :6080, then `exec obsidian`
- `vault-data/` — the live vault, bind-mounted at `/data/vault` (gitignored; never commit user notes)
- profile persisted in named volume `wattson-vault-profile` (`/home/ubuntu/.config/obsidian`)
- state/logs in named volume `wattson-vault-state` (`/data/state`)

Phase 0 validation artifacts (disposable — safe to delete once ADR 0001 is
no longer provisional):

- `fixtures/` — the original fixture notes used for the M0 verification checklist
- `test_vault/` — test vault fixture (its `.obsidian/` is gitignored)
- `digest-watch.log` — digest watcher log (gitignored)

## Run

```sh
just vault-build
just vault-up
just vault-logs
just vault-cli     # obsidian --help inside the container
just vault-shell
just vault-down
```

noVNC: container port 6080. Use the shim page, NOT bare `vnc.html`:

`https://1f47cd9b0.app.on.bigrock.dev/__preview/6080/wattson-vnc.html`

The shim redirects to `vnc.html?path=<prefix>/websockify&autoconnect=true`.
Required because noVNC 1.3 builds its WS URL as `wss://<host>/` + `path` with a
default `path='websockify'` — bare `vnc.html` dials `wss://<host>/websockify`,
which misses the pod preview proxy prefix and never reaches this container.
(`wattson-vnc.html` and a stub `package.json` are regenerated by
`entrypoint.sh` on every start; the Debian noVNC package ships neither.)

## Verification record (Phase 0, 2026-09-22)

1. app launches reliably under Xvfb
2. target test vault opens (first run: trust dialog — handled by pre-seeding
   `obsidian.json` in the profile volume)
3. `obsidian` CLI registers and works while the app is running
   (consult https://obsidian.md/help/cli for current subcommand syntax)
4. `tags`, `links`, `backlinks`, `tasks`, property ops, file creation,
   rename/move, search, and `eval` (JS against the app API / MetadataCache)
5. process survives container restart (profile on named volume)
6. Sync stability over days — open ADR 0001 condition; still being observed

## Notes

- Obsidian CLI requires a *running* desktop app; the CLI talks to the live
  instance (socket in the profile dir). If the CLI binary is not on PATH,
  inspect the .deb contents (`dpkg -L obsidian`) and the app resources.
- No GPU in this dev pod; Electron runs with `--disable-gpu`.
- Do not point this container at the real user vault.
